sbomx

Software Bill of Materials scanner & CVE vulnerability reporter

Generate CycloneDX 1.6 and SPDX 2.3 SBOMs and cross-referenced CVE reports from firmware, binaries, existing SBOMs, package manifests, and component lists. Built for TIC (Testing, Inspection, Certification) labs — IoT, automotive, and embedded products.

What it does

One tool from raw firmware to a shareable vulnerability report.

▣ SBOM generation

Valid CycloneDX 1.6 (JSON + XML) and SPDX 2.3 (JSON + tag-value) with purl + CPE identifiers and a vulnerabilities section.

◎ CVE engine

Concurrent async NVD + OSV lookups, SQLite cache, dedup, CVSS v3.1 scoring and severity banding. Pick sources with --source.

▤ Rich reports

JSON, a self-contained dark HTML dashboard (severity chart, sortable table, expandable CVE rows, JSON/CSV export), and VEX documents.

⌁ Binary analysis

Walks rootfs trees, detects ELF/PE, and extracts library versions — pure-Python fallback plus optional lief/libmagic.

⚑ Compliance-aligned

NTIA minimum elements, EO 14028, EN 18031, and UN R155 / ISO 21434 (evidence of detection method).

⇄ CLI + REST API

Six subcommands and a FastAPI service with Swagger UI. Docker & docker-compose included.

Quick start

Install, then point it at anything with components in it.

# install (core)
pip install .

# firmware directory → SBOM
sbomx scan ./firmware/ --format cyclonedx -o sbom.json

# any SBOM / manifest / component list → CVE report
sbomx cve -i sbom.json --source all -o cve-report.html

# end-to-end: input → SBOM + CVE report + VEX
sbomx full ./firmware/ --sbom-format spdx --cve-report html -d ./results/

# start the REST API (Swagger UI at /api/v1/docs)
sbomx serve --port 8000

Not on your PATH? Use python -m sbomx.cli … with the same arguments.

Inputs it understands

Format is auto-detected; override with --format if needed.

Firmware & binaries

Rootfs directories, ELF/PE files — version strings extracted and mapped to CPE/purl.

Existing SBOMs

CycloneDX (JSON/XML) and SPDX (JSON/tag-value). Convert between them with sbomx convert.

Package manifests

requirements.txt, package.json, pom.xml, go.sum, Cargo.toml, and more.

Component lists

JSON or CSV (name,version,vendor,type) — enter what you already know.

Scanner tables

Paste another scanner's output (a NAME/INSTALLED table) — components are extracted and re-scanned.

VEX suppression

Mark CVEs not_affected via --vex-input; they drop out of the counts.

REST API

Run sbomx serve — interactive docs at /api/v1/docs

POST /api/v1/scan     # upload binary/zip/manifest/SBOM → SBOM
POST /api/v1/cve      # upload SBOM/list → CVE report JSON
POST /api/v1/full     # upload → SBOM + CVE report
POST /api/v1/convert  # convert an SBOM between formats
GET  /api/v1/health   # health check
